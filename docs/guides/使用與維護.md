# Lotus Portfolio & Studio

繁體中文／英文個人作品集，搭配本機 PostgreSQL 與自訂 React 工作室。公開頁是 Next.js 靜態網站，GitHub Pages 不需要 Python、資料庫或管理 API。

目前已完成可操作的本機首版，程式碼已推送至[公開 GitHub 儲存庫](https://github.com/Lotus-030226/lotus-portfolio)；GitHub Pages 網站尚未發布。驗證紀錄見 [任務與進度](../status/任務與進度.md)。

## 日常使用

在本專案目錄執行：

```sh
python3 scripts/local.py start
```

- 工作室：<http://127.0.0.1:8100/studio/>
- 公開頁開發預覽：<http://127.0.0.1:3100>
- 完整靜態預覽：<http://127.0.0.1:3102>，需先在後台按「準備更新」。
- 本次建立的管理帳號保存在 `private/管理帳號.txt`，檔案權限 600，不進 Git。
- 停止：`python3 scripts/local.py stop`；狀態：`python3 scripts/local.py status`。停止會保留本案資料庫 volume。

後台可新增／編輯五類內容，切換中英欄位，管理封面和圖集，設定草稿／公開／精選，拖曳或按箭頭排序。儲存只更新本機；「準備更新」驗證雙語資料並匯出、建置靜態預覽，完成後再自行決定何時發布。內容的版本衝突會拒絕覆寫，請重新載入後整合修改。儲存、排序、重新載入與圖片寫入等待回應時，暫時鎖定表單與切換操作，避免新輸入被舊回應覆蓋。

圖片限 PNG、JPEG、WebP，10 MB／20 百萬像素以內，轉為最大 1920px WebP。圖片不需輸入描述；網站未有既存替代文字時會使用作品名稱與圖片序號。未引用或 hidden 的圖片保留本機，下一次匯出會移除先前公開目錄內已取消引用的圖片。

## 新機安裝

需要 Docker Desktop、Python 3.12 以上、Node.js 22 以上與 pnpm 11.19.0。安裝各自官方工具後：

```sh
python3 scripts/local.py setup
cms/.venv/bin/python cms/manage.py createsuperuser
python3 scripts/local.py start
```

`setup` 會建立本案虛擬環境、隨機 `.env` 機密、獨立 PostgreSQL 17 容器與初始內容。重跑 seed 不覆寫已編輯內容。工具會優先使用一般 PATH；本機沒有 Node／pnpm 時可使用 Codex 既有 bundled runtime。

本案服務：8100（Django）、3100（Next）、3101（選用 Vite）、3102（靜態預覽）、55433（PostgreSQL）。全部綁定 `127.0.0.1`。資料庫 volume 為 `lotus-portfolio_pgdata`，與其他專案隔離。後台是 `admin-ui/` 自訂介面，未掛載 Django 原版 admin。

## 手動更新 GitHub Pages

1. 在後台儲存內容，按「準備更新」，開啟靜態預覽核對中英文和圖片。準備／備份工作同時只允許一個；建置期間內容寫入短暫等待，避免混合快照。
2. 檢查 `git diff`，只提交公開程式、`src/content/generated/portfolio.json` 與 `public/assets/`。`.env`、`private/`、原始履歷、資料庫及後台編譯產物皆不進 Git。
3. 檢查並提交變更，再手動 push 至已建立的 `origin/main`。推送前確認公開快照、圖片及文案可公開。
4. Repository Settings → Pages 的來源選 GitHub Actions；Actions → **Publish portfolio manually** → Run workflow。
5. 本案使用 `site_url=https://Lotus-030226.github.io/lotus-portfolio`、`base_path=/lotus-portfolio`。若改用使用者首頁 repository（`username.github.io`），`base_path` 留空。自訂網域需自行設定 DNS／Pages。

Workflow 只有 `workflow_dispatch`，push 不會自動發布。CI 從已提交的公開快照建置，不連接本機 DB。正式網址只在建置時產生 canonical、sitemap 與分享圖完整網址；未設定時不虛構正式網址。

CLI 等效操作：

```sh
python3 scripts/prepare.py
# 純快照匯出（不建置）
cms/.venv/bin/python cms/manage.py prepare_release --kind export
# 明確驗證 GitHub 專案子路徑
SITE_URL=https://example.github.io/portfolio NEXT_PUBLIC_BASE_PATH=/portfolio pnpm build
```

一般 `pnpm build` 輸出 `out/`。後台預覽使用獨立 `.next-preview/` 靜態輸出，再成功替換 `private/preview/`；建置失敗保留上一份完成的預覽。修改 DB 不會自動改變線上版本。

## 備份與安全還原

後台「準備與備份」→「建立備份」，完成後下載 ZIP；CLI：

```sh
cms/.venv/bin/python cms/manage.py prepare_release --kind backup
cms/.venv/bin/python cms/manage.py restore_backup private/backups/你的備份.zip --database lotus_restore_mycheck
```

ZIP 包含 PostgreSQL custom dump、私人圖片／模型與 SHA-256 manifest，保存在 `private/backups/`。含管理帳號的密碼雜湊及非公開草稿，請保存在私人位置。還原先檢查路徑／雜湊，名稱必須以 `lotus_restore_` 開頭且資料庫與還原目錄均不存在，再核對內容筆數和圖片配對。它不會覆寫現用 DB／uploads，失敗的新 DB 保留供檢查。

若要使用已核對的還原版本，先停止服務，備份目前 `.env`，再自行修改 `.env` 的 `DB_NAME` 與 `LOTUS_UPLOADS_DIR=private/restores/lotus_restore_mycheck/uploads`，重新啟動；啟動工具會套用本案尚未執行的 migrations，使舊備份相容目前程式。還原版本中的未完成工作會標記停止。本次保留 `lotus_restore_validation_20260928` 作驗證證據。

## 開發與驗證

```sh
pnpm test
pnpm typecheck
pnpm lint
pnpm format:check
pnpm admin:build
cms/.venv/bin/python cms/manage.py check
cms/.venv/bin/python cms/manage.py test portfolio.tests --noinput
pnpm exec playwright install chromium
pnpm test:e2e
```

瀏覽器測試需要上述三個本機服務與 `private/test-login.json`（`{"username":"本機帳號","password":"本機密碼"}`，請設權限 600）。測試建立隨機 `e2e-draft-*` 草稿並清除該草稿；會建立測試圖片、真實預覽與備份。PostgreSQL suite 使用獨立 `test_lotus_portfolio` DB，不使用 SQLite。

## 內容與素材

參考 [Naresh Khatri 網站](https://nareshkhatri.dev/) 和 [3d-portfolio](https://github.com/Naresh-Khatri/3d-portfolio) 的空間／鍵盤概念；本案程式、3D 鍵盤、圖案均重新製作，未複製場景。桌面使用 Three.js，手機、reduced-motion、節省流量或 WebGL 失敗使用可操作的 CSS 鍵盤。後台「首頁設定 → 3D 模型與動畫」改為上傳 GLB（20 MB 以內、未壓縮且貼圖內含），網站直接以 Three.js 載入本地模型，透明背景、自動置中與配合容器縮放，不載入 Spline 公開頁或浮水印。舊 Spline 設定仍可讀取，但新介面不再提供網址欄位；設定模型時優先使用模型。

模型動畫在後台設定：上傳 GLB 後，可匯入含 `bindings` 的 JSON 動畫對照表，每筆包含 `technology`、`node`、`press`、`release`；也可逐筆選擇物件與動畫。觸發方式提供「滑鼠移入按下／移出放開」與「點擊後自動放開」。只有指定的動畫會播放，不自動播放整份模型。點擊時以技能名稱或 `sceneObjectName` 比對現有技術資料，不自動新增模型上的技能。已接入使用者提供的 24 鍵／48 動畫模型；原始模型與圖示順序圖保留於來源位置。

「作品專案 → 圖片與連結」直接上傳該作品封面與圖集，僅顯示此作品的圖片。滑鼠移入圖片或鍵盤聚焦時，右上角顯示 ×；觸控裝置常駐。移除後儲存作品，解除該作品的引用，保留私人原始素材及其他作品的引用。重新準備更新時，不再匯出未被公開內容引用的素材。可直接拖曳縮圖或用前後移動按鈕排序；第一張是封面，其餘依序放入圖集，不需圖片描述。首頁只展示公開且精選的作品，「查看完整作品集」連至 `/projects/`，展示所有公開作品。作品視窗的圖片含封面，採單張輪播：向左拖曳下一張、向右拖曳上一張，拖曳與箭頭均可首尾循環；圖片區保持固定比例，切換時按鈕不跳動。首頁入口位於專案標題右側，窄手機可換行；完整作品集的返回連結回到首頁專案區。

首版五作品由企劃書與履歷核對，截圖未提供時使用標明「概念示意圖」的原創圖案。MRI 只描述已完成技術成果，整體進行中；Dice／資料量以履歷記載呈現。電話、住址及原始 PDF 未納入公開資料。接案詳情、正式作品截圖／網址及實習結束日期仍待補；發布前需審閱文案。
